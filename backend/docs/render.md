# 🚀 RENDER DEPLOYMENT GUIDE

## Professional System for Software Engineers & Senior Developers

This guide provides step-by-step instructions for deploying the Cafeteria Project Management System to Render.com, focusing on best practices for security, database management, and scaling.

---

## STEP 1 — PRE-DEPLOYMENT CHECKLIST

Before deploying, ensure your project is pushed to a GitHub/GitLab repository. The project has been configured with:

- `render.yaml` (Infrastructure as Code) in the root directory.
- `backend/requirements.txt` with pinned package versions for reproducibility.
- `backend/.env.example` to demonstrate required environment variables without exposing secrets.
- Gunicorn set up with threaded workers for production WSGI serving.
- A robust `/health/` endpoint to ensure maximum uptime.

---

## STEP 2 — DEPLOYMENT VIA BLUEPRINT (Infrastructure as Code)

We use Render's Blueprint feature to deploy all components (Database, Backend, Frontend) simultaneously.

1. Push all recent code changes to your main branch on GitHub.
2. Log in to [Render Dashboard](https://dashboard.render.com).
3. Click on the **New +** button in the top right corner and select **Blueprint**.
4. Connect your GitHub repository containing the Cafeteria system.
5. Render will automatically detect the `render.yaml` file.
6. Click **Apply**.

Render will now provision the PostgreSQL database, build and deploy the Django Backend, and build and publish the React Frontend static site.

---

## STEP 3 — ENVIRONMENT VARIABLES & SECRETS

Most configuration is handled automatically by `render.yaml`. However, ensure you verify:

- **SECRET_KEY**: Auto-generated by Render.
- **DATABASE_URL**: Automatically injected from the attached database.
- **VITE_API_URL**: Used by the React frontend to communicate with the Django backend.
- **PYTHON_VERSION**: Explicitly set to `3.12.3` to ensure compatibility with backend dependencies like Pillow.

*Note: Never commit your `.env` file to version control.*

---

## STEP 4 — POST-DEPLOYMENT & HEALTH CHECKS

Once the deployment finishes, verify system health:

1. Hit the backend health endpoint:

   ```bash
   curl https://cafeteria-backend.onrender.com/health/
   ```

   You should receive a `{"status": "ok", "db": "connected"}` response.

2. Access the frontend application URL (`https://cafeteria-frontend.onrender.com`) to ensure the React app loads correctly.

---

## STEP 5 — DATABASE MIGRATION & RECOVERY

The backend build script automatically runs `python manage.py migrate`. However, if a deployment fails due to a bad migration, you can rollback the database manually.

### How to Rollback a Migration

1. Go to your Backend Web Service in the Render Dashboard.
2. Open the **Shell** tab.
3. Run the following command to rollback to the previous working migration state:

   ```bash
   # Replace 'your_app_name' with the specific app (e.g., 'accounts', 'inventory')
   # Replace '0001' with the target migration number you want to revert to.
   python manage.py migrate your_app_name 0001
   ```

## STEP 6 — SECURITY & COMPLIANCE

Your backend is hardened for production:

- **PGSSLMODE=require**: Enforces encrypted database connections.
- **WhiteNoise**: Serves static files efficiently via a robust CDN-compatible method.
- **CSRF & CORS**: `CSRF_TRUSTED_ORIGINS` is configured to explicitly allow the Render frontend URL, preventing 403 Forbidden errors on POST requests.
- **Security Headers**: Django is configured to enforce strict headers (`SECURE_HSTS_SECONDS`, `X_FRAME_OPTIONS='DENY'`, etc.) when `DEBUG=False`.

**Next Steps for Security** — run local dependency checks to avoid known CVEs:

```bash

pip install safety
safety check
cd ../frontend
npm audit
```

## Common Errors & Fixes

- **CSRF 403 Forbidden**: Ensure `CSRF_TRUSTED_ORIGINS` in the Render environment variables precisely matches the frontend URL.
- **Database Refusal**: If health check returns 503, wait 1-2 minutes for the newly provisioned PostgreSQL instance to initialize completely.
- **Missing Static Files**: Ensure `python manage.py collectstatic --noinput` runs successfully in the build command.
- **`requirements.txt` Not Found**: Render is trying to build from the repository root instead of the `backend/` folder. Ensure the **Root Directory** setting is set to `backend` in the Render Dashboard (or via `render.yaml`).
- **Pillow Installation Fails (`KeyError: '__version__'`)**: Render is using a bleeding-edge Python version (like 3.14+) that doesn't support the pinned `Pillow` version. Fix this by setting the `PYTHON_VERSION` environment variable to `3.12.3`.
