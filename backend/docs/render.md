# 🚀 Render Deployment Guide

This guide describes how to deploy the Cafeteria Project Management System on Render using the repository's `render.yaml` blueprint.

## What Deploys

The provided Render blueprint deploys:

- **PostgreSQL database**: `cafeteria-db`
- **Backend web service**: `cafeteria-backend`
- **Frontend static site**: `cafeteria-frontend`

## Render Service Configuration

### Backend service
- **Type**: web
- **Runtime**: python
- **Root directory**: `backend`
- **Build command**: `pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate`
- **Start command**: `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --worker-class gthread --threads 4 --timeout 120`
- **Health check path**: `/health/`

### Frontend service
- **Type**: web
- **Runtime**: static
- **Root directory**: `frontend`
- **Build command**: `npm install && npm run build`
- **Publish directory**: `dist`
- **SPA routing**: rewrites all unmatched routes to `/index.html`

### Database
- **Name**: `cafeteria-db`
- **Database name**: `cafeteria_prod`
- **Plan**: starter

## Required Environment Variables

Render automatically handles some values, but verify the following:

- `SECRET_KEY` — should be generated by Render
- `DEBUG` = `False`
- `ALLOWED_HOSTS` = `cafeteria-backend.onrender.com`
- `CORS_ALLOWED_ORIGINS` = `https://cafeteria-frontend.onrender.com`
- `CSRF_TRUSTED_ORIGINS` = `https://cafeteria-frontend.onrender.com,https://cafeteria-backend.onrender.com`
- `DATABASE_URL` — injected by the database service
- `PGSSLMODE` = `require`
- `PYTHON_VERSION` = `3.12.3`
- `VITE_API_URL` = `https://cafeteria-backend.onrender.com/api/`

## Post-Deployment Validation

Once the deployment completes:

1. Check the backend health endpoint:
   ```bash
   curl https://cafeteria-backend.onrender.com/health/
   ```
   Expected response:
   ```json
   {"status": "ok", "db": "connected"}
   ```

2. Open the frontend URL and confirm the app loads.

## Common Deployment Issues

- **403 CSRF error**: Verify `CSRF_TRUSTED_ORIGINS` matches the frontend and backend URLs exactly.
- **503 database error**: Wait for the Render database to initialize and retry.
- **Static files missing**: Confirm `collectstatic --noinput` completed successfully.
- **Backend build from wrong folder**: Ensure the backend service root is set to `backend`.
- **Pillow or Python version mismatch**: Use `PYTHON_VERSION=3.12.3` to match the pinned dependencies.

## Rollback and Recovery

If a migration causes issues, use Render's shell for the backend service and run:

```bash
python manage.py migrate <app_name> <migration_name>
```

For example:

```bash
python manage.py migrate accounts 0001
```

## Security Notes

- Production uses `SECURE_SSL_REDIRECT` and secure cookies when `DEBUG=False`.
- The `/health/` endpoint verifies both application and PostgreSQL connectivity.
- Static assets are served through WhiteNoise in production.
